# 거꾸로 신분증 — 시연 웹 ROUND 1

`index.html`을 직접 열면 됩니다. 서버·빌드·CDN 없이 실행하며 글꼴도 함께 들어 있습니다. GitHub Pages에는 이 디렉터리의 내용을 그대로 배치합니다. 기존 화면은 `../web-old/`에 보관했습니다.

## 장면과 핵심 동작

| 장면 | 주소 | 직접 눌러 볼 동작 |
|---|---|---|
| 1 첫 실행 | `#scene-1` | 시작 → 큰 글씨·음성 → 신뢰목록 → 카메라 선택 |
| 2 정상 대면 | `#scene-2` | 직원 QR → 실제 서명 검증 → 초록 결과·기록 |
| 3 위조 대면 | `#scene-3` | 같은 기관 이름의 다른 서명 → 빨강 → 가족 공유·의심 신고 |
| 4 캡처 재사용 | `#scene-4` | 60초 전 QR → 만료 → 현재 QR 다시 요청 |
| 5 퇴직자 | `#scene-5` | 폐지된 자격 → 거절 |
| 6 정상 전화 | `#scene-6` | 직원의 60초 1회용 번호 → 시민 입력 → 초록 |

| 8 현장 예외 | `#scene-8` | 카메라 거부·오프라인 → 저장한 목록으로 검증·재연결 |

장면 3의 ‘다른 의심 QR 확인하기’에는 미등록 기관·다른 기기·일반 링크 QR도 있습니다. 모든 경우 실제 프로토콜 입력을 만들어 검사합니다. 확인 기록 검색·필터·빈 상태·삭제 되돌리기·CSV·인쇄/PDF 저장, 큰 글씨, 한국어 음성, 공유 취소·미지원 안내, 문의 내용 파일 저장을 포함합니다.

## 파일과 실행 방식

- `index.html`, `style.css`, `app.js`: 화면·디자인 토큰·상호작용. `data.js`: 공개 시험용 발급키와 신뢰목록.
- `protocol.mjs`: 기존 ECDSA P-256 검증 원본 그대로. HTTPS에서는 이 모듈을 실제 import합니다.
- `protocol.browser.js`: 원본의 `export`만 제거하고 IIFE로 감싼 동일 코드. 브라우저의 `file://` 모듈 제한을 피하기 위한 사본입니다. `verify.mjs`가 원본·사본의 소스와 공개 API 동등성을 검사합니다.
- `check.html`: 실제 휴대폰으로 직원 QR을 찍었을 때 열리는 검증 화면. 배포 경로 아래 상대주소로 동작합니다.
- `trust.json`, `revoked.json`, `demo-issuer-key.json`: 기존 공개 시험 fixture 보존. `demo-issuer-key.json`은 이미 공개된 시험 전용 키이며 운영 비밀키가 아닙니다. 실제 신분 증명에 사용하면 안 됩니다.
- `fonts/`, `vendor/`: 오프라인 자산과 라이선스.
- `shot.mjs`: 외부 Claude가 실행할 브라우저 캡처 스크립트.
- `verify.mjs`: Node 프로토콜 회귀 검사.

## 검증과 캡처

```sh
node --check poc/web/app.js
node poc/web/verify.mjs
PW_ROOT=/absolute/path/to/node_modules node poc/web/shot.mjs
```

`PW_ROOT`는 `playwright`가 설치된 `node_modules` 디렉터리입니다. 스크립트에서 `createRequire(process.env.PW_ROOT + '/')('playwright')`로 불러옵니다. 기본은 로컬 `file://`이며, `DEMO_URL` 환경변수로 배포 주소를 지정할 수 있습니다.

각 장면의 390×844·1280×800 기본 화면은 `_codex/shots/demo-<장면>-<폭>.png`, 결과는 `-result.png`입니다. 온보딩 바텀시트와 관리자 신고 목록도 추가 촬영하여 총 36장을 저장합니다. 3·7번 장면에서 의심 신고도 제출하므로 9번에 실제로 표시됩니다. 가로 넘침·콘솔 오류는 `demo-checks.json`에 기록하고 실패 시 종료코드 1을 반환합니다.

이번 제작에서 실행한 항목: JavaScript 구문 검사, 기존 13개 프로토콜 시나리오, LinkeDOM 상호작용 검사 20개, 정적·렌더링 HTML 22개 태그 균형 검사, 주요 텍스트 색 대비 검사(최소 5.81:1). DOM 검사 결과는 `../../_codex/demo-dom-results.json`에 있습니다. DOM 검사는 실제 브라우저의 화면 배치를 검증하지 않습니다. 요청대로 `shot.mjs` 실행은 외부 Claude에 남겼습니다.

## 디자인

7개 기준색: 남색 `#193a5b`, 본문 `#182b3e`, 회색 `#586775`, 흰색 `#ffffff`, 성공 `#116548`, 경고 `#80540c`, 위험 `#a93036`. 선·배경·옅은 상태색은 기준색에서 파생합니다. 글자 단계는 12/14/16/20/28/36px, 간격은 4px 배수, 주요 배치는 8px 그리드, 둥글기는 12/24px, 그림자는 2단계, 전환은 180ms입니다. 숫자는 고정폭 숫자를 사용합니다. 버튼은 최소 48px, 키보드 포커스·동작 줄이기 설정을 지원합니다.

첫 화면은 시민 앱이며, 설명은 데스크톱 오른쪽 패널과 상단 시연 띠에만 둡니다. 휴대폰에서는 직원 화면을 바텀시트로 보고, 넓은 화면에서는 직원·시민 화면이 나란히 놓입니다. 성공·실패 화면은 각각 초록·빨강 전체 배경입니다.

## 구현 범위와 남은 검증

전자서명은 실제로 수행하지만, 모바일신분증·인사·경찰 신고 시스템과 연결하지 않은 브라우저 내 모델입니다. 직원 시험용 기기키도 브라우저 저장소에 보관합니다. 보안영역이나 운영용 인증을 구현한 것은 아닙니다. 시민 앱·기관 화면의 기록과 신고는 같은 출처의 `localStorage`로 연결됩니다. 시민 확인 기록과 의심 신고는 앱을 열 때 30일 보관 기간을 적용합니다. 저장소가 막힌 브라우저에서는 현재 창 메모리만 사용합니다.

카메라 접근 선택은 앱 안의 권한 흐름이며 실제 카메라 스트림을 열지 않습니다. 화면의 ‘이 QR 확인하기’는 해당 QR 토큰을 검사하는 버튼입니다. 다른 휴대폰의 기본 카메라로 PC의 직원 QR을 읽는 경로는 유지했습니다. **로컬 파일에서 만든 QR은 기존 공개 주소 `https://gooreum.github.io/geokkuro-poc/check.html`로 향하므로 새 버전을 그 주소에 배포해야 새 확인 화면이 열립니다.** 이번 작업에서 배포하지 않았습니다.

전화번호는 기존 `createCallCodeServer()`를 사용합니다. 실제 서버 대신 현재 탭 메모리에 저장하므로 탭을 새로 열면 새 번호를 발급해야 합니다. 5회 오입력 잠금은 5분간 기기에 유지합니다. 다른 기기 간 전화번호 공유 서버는 구현하지 않았습니다.

오프라인 QR 검증은 앱과 신뢰목록을 이미 열어 둔 상태 또는 로컬 파일에서 동작합니다. 최초 오프라인 웹 방문용 서비스 워커는 없습니다. 마지막 동기화 이후의 폐지는 확인할 수 없음을 결과 화면에 알립니다. 새 기기에 관리자 폐지목록을 배포하는 운영 서버도 없습니다. 실제 112 연결·가족 메시지 전송은 수행하지 않았으며, 사용자가 전화·공유 화면에서 직접 선택합니다.

실기기 카메라 인식률·음성 재생·Safari/오래된 Android 호환성·브라우저 실제 가로 넘침·시각적 완성도는 후속 스크린샷 및 실기기 검증 대상입니다. 인쇄 기능은 브라우저의 PDF 저장을 이용합니다.
